# Fizzler

Fizzler is a lo-fi glitch effect built with [JUCE](https://juce.com). It mangles audio by scrambling sample order with bitwise operations, layering block-based delay taps, and smearing the signal with running averages. It ships as a **VST3** plugin and a **standalone** app.

## Controls

The editor shows eight vertical sliders, left to right:

| Slider | Range | Default | What it does |
| --- | --- | --- | --- |
| **Phase** | 0 – 64 | 1 | Scrambles sample order. Each output sample is read from index `i <op> Phase` within the current block, where `<op>` is set by **Mode**. |
| **Dry/Wet Phase** | 0 – 1 | 0 | Blend between the dry signal and the scrambled one. |
| **Mode** | 0 – 2 | 1 | Bitwise operator used by Phase: `0` = AND, `1` = OR, `2` = XOR. |
| **Spray** | 1 – 3 | 1 | Adds extra delay taps around the main tap (at `Delay ± Spray / j`), for a smeared, scattered echo. |
| **Delay** | 0 – 511 | 1 | How many audio blocks back the delay tap reads. `0` turns the delay off. |
| **Dry/Wet Delay** | 0 – 1 | 0 | How much of each delay tap is mixed in. |
| **Spread** | 0 – 32 | 0 | Every Nth sample gets blended with a forward and backward running average of the block (up to 10,000 samples each way). Higher values hit fewer samples. |
| **Dry/Wet Spread** | 0 – 1 | 0 | How much of the Spread average is mixed in. |

All three Dry/Wet controls default to 0, so a fresh instance passes audio through unchanged.

### Things to know

- **Delay time depends on your host's buffer size.** Delay counts whole processing blocks, not milliseconds, so at 512 samples / 48 kHz one step is about 10.7 ms. Changing the buffer size in your DAW changes the delay.
- **Phase and Spread work within the current block,** so their character also changes with buffer size.
- The plugin accepts mono or stereo, with matching input and output layouts.
- In hosts, the parameters show up for automation under their display names (Phase, Delay, and so on). Their internal IDs are `Slider 1` to `Slider 8`, which is what saved sessions store.

## Building

### Requirements

- Windows with **Visual Studio 2026** (Desktop development with C++)
- **JUCE 8.0.12** and the Projucer

### Steps

1. Get JUCE 8.0.12. The project expects its modules at
   `C:\Users\<you>\Downloads\juce-8.0.12-windows\JUCE\modules`. If yours are somewhere else, open [fizzler.jucer](fizzler.jucer) in the Projucer, update the module paths under **Exporters → Visual Studio 2026**, and save to regenerate the build files.
2. Open [Builds/VisualStudio2026/fizzler.sln](Builds/VisualStudio2026/fizzler.sln).
3. Choose the **Debug** or **Release** configuration with the **x64** platform, then build the solution.

Build outputs land in `Builds/VisualStudio2026/x64/<Configuration>/`:

- `VST3/fizzler.vst3` is the plugin.
- `Standalone Plugin/fizzler.exe` is the standalone app.

### Installing the VST3

Copy `fizzler.vst3` into `C:\Program Files\Common Files\VST3\`, then rescan plugins in your DAW.

## Project layout

```
fizzler/
├── fizzler.jucer          Projucer project (edit settings here, not in the .vcxproj files)
├── Source/
│   ├── PluginProcessor.*  DSP: parameter layout, delay line, processBlock
│   └── PluginEditor.*     UI: the eight sliders and their parameter attachments
├── JuceLibraryCode/       Generated by the Projucer
└── Builds/VisualStudio2026/  Generated VS solution and projects
```

`JuceLibraryCode/` and `Builds/` are regenerated whenever you save in the Projucer, so don't hand-edit them.
